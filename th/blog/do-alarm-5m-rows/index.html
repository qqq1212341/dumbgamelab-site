alarm ตัวเดียวใช้โควตาอ่าน 5 ล้านแถวต่อวันหมด: ไล่หา error 1101 ของ Durable Objects

Justin Lee, Dumb Game Lab · 2026-11-10

วันที่ 7 พฤศจิกายน เซิร์ฟเวอร์เก็บ error เริ่มตอบ 500 โดยรหัส error คือ 1101 พร้อมข้อความ «Exceeded allowed rows read» ตัวการคือ alarm ที่ทำงานทุก 5 วินาทีของเซิร์ฟเวอร์เกม (도트혈맹) ในบัญชีเดียวกัน alarm นี้สแกนตาราง users กับ feed โดยไม่มี index และอ่านไปคนเดียว 4.98 ล้านแถว จากโควตา 5 ล้านแถวต่อวัน โควตานี้ทั้งบัญชีใช้ร่วมกัน เซิร์ฟเวอร์ชวนเพื่อนกับเซิร์ฟเวอร์เก็บ error จึงล่มตามไปด้วย ผมแก้ด้วย index 2 ตัวกับแคช 10 นาที ตอนนี้ทุกชั่วโมงผมวัดจำนวนแถวที่แต่ละเซิร์ฟเวอร์อ่าน ถ้าเกิน 60% จะมีแจ้งเตือนพร้อมชื่อตัวการ

สารบัญ

  1. ดูตัวเลขก่อน
  2. แรก ๆ ผมสงสัยผิดเซิร์ฟเวอร์
  3. ตัวการคือ alarm 5 วินาที
  4. สิ่งที่แก้
  5. กันไม่ให้เกิดซ้ำ
  6. สิ่งที่ผมพลาด

ดูตัวเลขก่อน

พอรู้ว่าเซิร์ฟเวอร์เก็บ error ล่ม สิ่งแรกที่ผมทำคือรวบรวมตัวเลข โควตาอยู่ที่เท่าไร และใครอ่านไปเท่าไร

รายการตัวเลขหมายเหตุ
โควตาอ่านต่อวัน (ฟรี)5 ล้านแถวทุกเซิร์ฟเวอร์ในบัญชีใช้ร่วมกัน รีเซ็ตตอน 00:00 UTC (9 โมงเช้าเวลาเกาหลี)
alarm ตัวเดียวของ 도트혈맹4.98 ล้านแถวยอดรวมทั้งวันของวันที่ 7 พฤศจิกายน
จำนวนครั้งที่ alarm ทำงานวันละ 17,280 ครั้งทุก 5 วินาที เอา 86,400 วินาทีหารด้วย 5
แถวที่อ่านต่อครั้งประมาณ 290 แถวค่าที่คำนวณได้: 4.98 ล้านหารด้วย 17,280
request ที่เข้าเซิร์ฟเวอร์เก็บ errorวันละ 2-3 พันแถวที่อ่านอยู่ที่ 1.4 ล้านถึง 5.14 ล้านต่อวัน

แรก ๆ ผมสงสัยผิดเซิร์ฟเวอร์

อาการโผล่ที่เซิร์ฟเวอร์เก็บ error ก่อน พอเรียกรายการ session กับรายการ issue จะตอบ 500 และเนื้อหามีแค่ error code: 1101 ในเวลาเดียวกันเซิร์ฟเวอร์ชวนเพื่อนก็ล่มด้วยรหัสเดียวกัน

แถบแจ้งเตือนด่วนระบุว่าเซิร์ฟเวอร์ชวนเพื่อนคือตัวการ คือระบบเขียนชื่อเซิร์ฟเวอร์ที่ล่มเป็นตัวการเลย แต่เซิร์ฟเวอร์ชวนเพื่อนมี request ต่อวันแค่ไม่กี่พัน สร้างการอ่านขนาดนั้นไม่ได้

เซิร์ฟเวอร์เก็บ error ก็เหมือนกัน request แค่ 2-3 พันต่อวัน แต่แถวที่อ่านอยู่ที่ 1.4 ล้านถึง 5.14 ล้าน ถ้าจำนวน request กับแถวที่อ่านไม่ตรงกันขนาดนี้ แปลว่าไม่ใช่ request ที่อ่าน แต่มีตัวอื่นกำลังอ่านอยู่

ตัวการคือ alarm 5 วินาที

โควตานี้ทั้งบัญชีใช้ร่วมกัน ผมเลยต้องดูการใช้แยกตามเซิร์ฟเวอร์ ผมดึงแถวที่อ่านของแต่ละเซิร์ฟเวอร์ (worker) ผ่าน Cloudflare API ปรากฏว่าเกือบทั้งหมดอยู่ที่เดียว คือเซิร์ฟเวอร์เกม 도트혈맹

เซิร์ฟเวอร์นี้มี alarm ทำงานทุก 5 วินาที ใน alarm มี query นับจำนวนคนที่ออนไลน์และอ่านรายชื่อบอต ตาราง users กับ feed ไม่มี index ทุกครั้งที่ query ทำงานจึงสแกนตารางตั้งแต่ต้นจนจบ

290 แถวต่อครั้งดูน้อย แต่ alarm ทำงานวันละ 17,280 ครั้ง คูณกันแล้วได้ 4.98 ล้าน

สิ่งที่แก้

ผมแก้ทั้งเซิร์ฟเวอร์ 도트혈맹 และเซิร์ฟเวอร์เก็บ error สาเหตุของทั้งสองที่เหมือนกันคือ query แบบช่วงที่ไม่มี index

  • แม้ deploy ตัวที่แก้แล้ว โควตาของวันนั้นก็หมดไปแล้ว เซิร์ฟเวอร์เลยไม่กลับมาทันที เซิร์ฟเวอร์เก็บ error จะกลับมาตอนรีเซ็ตรอบถัดไป (00:00 UTC)
  • พอมี index จำนวนแถวที่อ่านต่อครั้งจะลดจากขนาดทั้งตารางเหลือเท่าที่ต้องใช้จริง
เซิร์ฟเวอร์สิ่งที่เปลี่ยน
도트혈맹index 2 ตัว: users(bot, seen) และ feed(bot, ts)
도트혈맹แคชรายชื่อบอตในหน่วยความจำ 10 นาที
เซิร์ฟเวอร์เก็บ errorindex issues(last_at) และ hits(day)
เซิร์ฟเวอร์เก็บ errorลบ hits และ sessions ที่เก่ากว่า 90 วัน วันละครั้ง

กันไม่ให้เกิดซ้ำ

แก้อย่างเดียวไม่พอ รอบนี้ผมรู้ตอนที่โควตาหมดไปแล้ว และกว่าจะรู้ว่าใครใช้ก็ผ่านไปนาน ผมเลยเพิ่มอีกสองอย่าง

อย่างแรกคือเทสต์ ให้ alarm ทำงาน 400 รอบ แล้วเก็บ query ที่รันไปดูแผนด้วย EXPLAIN QUERY PLAN ถ้ามี query แม้แต่ตัวเดียวที่สแกน users หรือ feed โดยไม่มี index เทสต์จะล้มเหลว query ที่มี LIMIT และหยุดตั้งแต่ต้นไม่นับ

อย่างที่สองคือการเฝ้าดู ทุกชั่วโมงที่นาทีที่ 7 ระบบรวมแถวที่อ่านของแต่ละเซิร์ฟเวอร์ ถ้าเกิน 60% ของโควตาจะส่งแจ้งเตือนพร้อมชื่อเซิร์ฟเวอร์ตัวการและจำนวนแถว ผมยังยิงตรงไปที่เซิร์ฟเวอร์ชวนเพื่อนกับเซิร์ฟเวอร์เก็บ error ถ้าเจอ 1101 ก็แจ้ง และเลิกแจ้งเมื่อกลับมาปกติ

สิ่งที่ผมพลาด

สิ่งที่พลาดไม่ใช่ query ตัวเดียว เซิร์ฟเวอร์หลายตัวใช้โควตาฟรีก้อนเดียวร่วมกัน แต่ไม่มีที่ไหนวัดว่าแต่ละตัวอ่านเท่าไร พอเซิร์ฟเวอร์หนึ่งใช้โควตาหมด เซิร์ฟเวอร์ที่ไม่ผิดก็ล่มแทน และเรามองเห็นแต่ตัวที่ล่ม

ผมเลยใส่เทสต์ใน 도트혈맹 เพื่อตรวจว่า query บนเส้นทางของ alarm ใช้ index หรือไม่ รอบนี้ผมได้เรียนรู้ว่าถ้าโควตาใช้ร่วมทั้งบัญชี ต้องมีตารางการใช้แยกตามเซิร์ฟเวอร์ก่อน

FAQ

error 1101 ของ Cloudflare Durable Objects หมายถึงอะไร

อาจหมายถึงใช้เกินโควตาฟรี ในกรณีของผม เนื้อหามีข้อความ «Exceeded allowed rows read» ด้วย แปลว่าใช้โควตาแถวที่อ่านต่อวันหมดแล้ว (5 ล้านแถวทั้งบัญชี)

โควตาอ่านของ Durable Objects นับแยกตามเซิร์ฟเวอร์หรือทั้งบัญชี

ในบัญชีของผม ทั้งบัญชีใช้ร่วมกัน 5 ล้านแถวต่อวัน พอเซิร์ฟเวอร์หนึ่งใช้เกือบหมด อีกสองตัวก็หยุดตามไปด้วย

ถ้าโควตาหมดแล้ว แก้เซิร์ฟเวอร์แล้วจะกลับมาทันทีไหม

ไม่ทันที แม้แก้และ deploy แล้ว โควตาของวันนั้นก็ยังเท่าเดิม ผมต้องรอรีเซ็ตตอน 00:00 UTC (9 โมงเช้าเวลาเกาหลี)

จะรู้ได้อย่างไรว่า alarm สแกนทั้งตาราง

เก็บ query ที่รันใน alarm แล้วลองรัน EXPLAIN QUERY PLAN ถ้าแผนมี SCAN ชื่อตาราง โดยไม่มี index แปลว่าอ่านทั้งตาราง
