วันที่ผมรายงานว่าแก้บั๊กที่แก้ไปแล้วซ้ำถึง 16 รอบ

Justin Lee, Dumb Game Lab · 2026-11-12

ข้อผิดพลาดที่เข้ามาที่ตัวเก็บ crash ไม่ได้เป็นบั๊กใหม่ทั้งหมด ผมตรวจตั๋วข้อผิดพลาดที่เปิดในวันเดียวคือ 3 พฤศจิกายน พบว่า 16 ใบเป็นบั๊กที่แก้ใน main ไปแล้ว และแอปที่ส่งข้อผิดพลาดมาเป็นเวอร์ชันเก่าก่อนแก้ ก่อนจะนับข้อผิดพลาด ให้ดูก่อนว่าเวอร์ชันแอปที่ส่งมาต่ำกว่าเวอร์ชันที่แก้แล้วหรือไม่

3 พฤศจิกายน: ผมเปิดตั๋ว 16 ใบ แต่ไม่มีอะไรให้แก้

ผมขอเริ่มจากตัวเลขที่เขียนไว้ในบันทึกของวันนั้น มี PR ที่ตรวจแล้วปิดตั๋วข้อผิดพลาด 16 รายการ และทุกรายการเป็น «แก้ใน main ไปแล้ว» ที่นับจากชื่อเรื่องได้ 13 รายการ ส่วนอีก 3 รายการใช้ถ้อยคำต่างออกไป

ตัวอย่างคือ «ปิดตัวผิดปกติ» ของ Dongne Bakery (#5259), «ดับโดยไม่มีสัญญาณที่หน้าจอก่อนหน้า» ของเกมจิมจิลบัง (#5263), «ปิดตัวผิดปกติ» ของ Teolmungchi (#5287) และข้อผิดพลาดบนมือถือ 3 รายการของ Wakppu Tower (#5307) พอเปิดดูแล้วสรุปตรงกัน คอมมิตที่แก้อยู่ใน main ตั้งแต่แรก และในโค้ดไม่มีอะไรต้องทำ

การตรวจตั๋วหนึ่งใบใช้เวลา ต้องหาลายนิ้วมือของข้อผิดพลาด ดูว่าเกิดในเวอร์ชันไหน แล้วหาคอมมิตที่แก้มาเชื่อมกัน โค้ดไม่เปลี่ยนสักบรรทัด แต่เวลานั้นหมดไป 16 รอบ

ตัวที่ส่งข้อผิดพลาดมาคือแอปก่อนแก้

สาเหตุไม่ใช่ข้อผิดพลาดเกิดใหม่ แต่เป็นแอปเก่าที่ส่งมาเรื่อย ๆ คนที่ไม่ได้อัปเดตในสโตร์แอปก็ยังใช้เวอร์ชันก่อนแก้อยู่ พอแอปนั้นค้าง ตัวเก็บ crash ก็บันทึกเป็นข้อผิดพลาดใหม่หนึ่งรายการ

#5276 เป็นข้อผิดพลาดที่ส่งมาจาก Wakppu Tower 1.0.17 เท่านั้น และ #5275 ส่งมาจากเกมรวมขนมปัง 1.0.3 เท่านั้น ส่วน #5258 ตั้งแต่ 1.0.4 ขึ้นไปเกิดซ้ำ 0 ครั้ง ตัวเลขนี้บอกว่า «เวอร์ชันหลังแก้ไม่เกิด» แต่ตัวเก็บ crash ไม่สนเลขเวอร์ชัน และนับข้อผิดพลาดเดียวกันเป็นข้อผิดพลาดเดียวกัน

การตัดสินที่ผิดอย่างหนึ่ง: ผมเชื่อว่าข้อผิดพลาดที่เข้ามาคือบั๊กใหม่

ตอนสร้างตัวเก็บ crash ผมสมมติว่า «ข้อผิดพลาดเข้ามาหนึ่งรายการ แปลว่ามีบั๊กที่ต้องแก้เพิ่มหนึ่งตัวตอนนี้» สมมติฐานนี้สร้างจากลำดับที่ข้อผิดพลาดเข้ามาเท่านั้น และผมไม่ได้ถามว่าข้อผิดพลาดนั้นเกิดจากโค้ดของช่วงเวลาไหน

ผมแก้เร็ว แต่คนอัปเดตไม่ได้เร็วเท่า ยิ่งแก้บั๊กไปมาก ทางที่ «บั๊กที่แก้แล้ว» จะกลับมาจากเวอร์ชันเก่าก็ยิ่งเพิ่มตามไปด้วย

บรรทัดที่สองของหัวข้อ «ความสูญเปล่าของวันนี้» ในบันทึกวันนั้นคือ 16 รายการนี้ ผมใช้ PR หนึ่งอันต่อหนึ่งรายการ แต่โค้ดที่เปลี่ยนเป็น 0

หลังแก้แล้ว ยังมี PR แบบเดิมเพิ่มอีก 29 อันในสิบวัน

ในรายการงานของพรุ่งนี้ ผมเขียนว่า «ข้อผิดพลาดของเวอร์ชันเก่าไม่ต้องสร้างตั๋ว ให้จดลงสมุดบัญชีอย่างเดียว ถ้าเลขเวอร์ชันต่ำกว่า main ให้ถูกกรองออก เริ่มจากตัวเก็บ crash ก่อน» (t-261103-bszc)

หลังจากนั้นถึงวันที่ 11 พฤศจิกายน ผมนับ PR ข้อผิดพลาดที่ชื่อเรื่องมีคำว่า «แก้แล้ว» ตั้งแต่วันที่ 1 พฤศจิกายน รวมได้ 42 รายการ หักของวันที่ 3 พฤศจิกายน 13 รายการออก 8 วันหลังจากนั้นมี 29 รายการ ค่าเฉลี่ยต่อวันลดจาก 13 เหลือ 3 ถึง 4 แต่ไม่ใช่ 0

#6070 เกมรวมขนมปัง 1.0.3, #6377 เกมร้านเน็ต 2.0.37 และ #6473 Algoitneun Yeou 1.0.6 คือตัวอย่าง แม้เวอร์ชันที่แก้แล้วจะออกมา เวอร์ชันเก่าก็ยังอยู่ไปอีกนาน ตัวเลขนี้นับจากชื่อ PR จึงไม่รวมกรณีที่ชื่อเรื่องใช้ถ้อยคำต่างออกไป

ช่วงเวลาPR ข้อผิดพลาดที่ชื่อเรื่องมีคำว่า «แก้แล้ว»
3 พฤศจิกายน หนึ่งวัน13 รายการ
4 ถึง 11 พฤศจิกายน (8 วัน)29 รายการ
รวม 1 ถึง 11 พฤศจิกายน42 รายการ

สิ่งที่ผมเปลี่ยนจากเรื่องนี้

พอข้อผิดพลาดเข้ามา ผมดูสองอย่างก่อนจะดูจำนวน คือเลขเวอร์ชันของแอปที่ส่งมา และเวอร์ชันแรกที่มีคอมมิตแก้ข้อผิดพลาดนั้น ถ้าเวอร์ชันที่ส่งมาต่ำกว่าเวอร์ชันที่แก้แล้ว ก็ไม่ใช่บั๊กใหม่ แต่เป็นรายงานจากเวอร์ชันเก่า

ผมยังเพิ่มวิธีจดเลขคอมมิตที่แก้ลงสมุดบัญชีข้อผิดพลาดบรรทัดเดียวด้วย แบบนี้พอลายนิ้วมือเดิมเข้ามาอีก สมุดบัญชีจะขึ้นทันทีว่า «แก้แล้ว คอมมิตไหน ตั้งแต่เวอร์ชันไหน» ฝั่งตั๋วผมเปลี่ยนให้จดแท็กเป็นรายคอมมิต (#5316)

ถ้าคุณอยู่ในสถานการณ์เดียวกัน ลองทำสิ่งนี้ก่อน

ถ้าคุณเป็นนักพัฒนาคนเดียวที่ติดตั้งระบบตรวจจับ crash เอง ลำดับนี้จะช่วยประหยัดเวลา ชื่อเครื่องมือต่างกัน แต่ส่วนใหญ่มีตัวกรองตามเวอร์ชันแอป

ยังมีสิ่งที่ผมทำไม่เสร็จ การกรองข้อผิดพลาดที่เลขเวอร์ชันต่ำออกอัตโนมัติก่อนสร้างตั๋ว ตอนนี้ทำไปถึงไหนแล้ว ผมไม่ได้ตรวจซ้ำในโค้ดตอนเขียนบทความนี้ สิ่งที่แน่ใจคือ เวลาผ่านมาเกือบสิบวันแล้ว ตอนนี้ก็ยังมี PR ที่ต้องเปิดตรวจแล้วปิดอยู่

  • ก่อนนับข้อผิดพลาด ให้แยกตามเวอร์ชันแอปก่อน
  • จดเลขเวอร์ชันแรกที่มีคอมมิตแก้ไว้ในสมุดบัญชี
  • ถ้าเวอร์ชันที่ส่งมาต่ำกว่านั้น ไม่ต้องเปิดตั๋ว จดลงสมุดบัญชีอย่างเดียว
  • ดูความเร็วที่เวอร์ชันเก่าลดลง แล้วพิจารณาว่าต้องบังคับอัปเดตหรือไม่

FAQ

ทำไมบั๊กที่แก้แล้วถึงโผล่ในรายงาน crash ของแอปซ้ำ ๆ

เพราะบนมือถือของผู้ใช้ที่ไม่ได้อัปเดต แอปเวอร์ชันเก่ายังทำงานอยู่ พอแอปนั้นค้าง ข้อผิดพลาดจากโค้ดก่อนแก้ก็เข้าไปที่ตัวเก็บ crash เหมือนเป็นรายการใหม่ การแยกดูตามเวอร์ชันแอปจะช่วยแยกได้

จะกรองข้อผิดพลาดจากแอปเวอร์ชันเก่าออกได้อย่างไร

จดเลขเวอร์ชันแรกที่มีคอมมิตแก้ข้อผิดพลาดไว้ในสมุดบัญชี ถ้าเวอร์ชันที่ส่งมาต่ำกว่านั้นก็ไม่นับเป็นบั๊กใหม่ เครื่องมือตรวจจับ crash ส่วนใหญ่รองรับตัวกรองตามเวอร์ชันแอป ลองใช้ตัวนั้นก่อน

หลังเวอร์ชันที่แก้แล้วออก ผู้ใช้เวอร์ชันเก่าจะเหลืออยู่นานแค่ไหน

ต่างกันไปตามแต่ละแอป จากตัวเลขในบทความนี้ แม้ใน 8 วันหลัง 3 พฤศจิกายนก็ยังมี PR ที่ปิดเพราะข้อผิดพลาดของเวอร์ชันเก่า 29 รายการ สัดส่วนผู้ใช้ที่แน่นอนผมไม่ได้นับไว้ จึงไม่ทราบ
