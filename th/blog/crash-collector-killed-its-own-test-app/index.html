บันทึกความผิดพลาดของนักพัฒนาเกมคนเดียว

ผมตั้งใจทำให้แอปเด้งออกเพื่อทดสอบตัวเก็บ crash แต่แอปไม่เด้ง

Justin Lee, Dumb Game Lab · 2026-10-27

ผมติดตัวเก็บ error ไว้ในเกมหลายเกม เพื่อให้มือถือแจ้งทันทีที่แอปพัง และสัปดาห์แรกประเมินพลาดไปสองครั้ง ปุ่มที่ตั้งใจให้แอปเด้งออกไม่สามารถทำให้แอปดับบน iPhone เครื่องจริง ส่วน error ตอนเปิดแอป 2 รายการที่เข้ามาทันทีหลังอัปโหลดขึ้น Play ก็ไม่ใช่ของผู้ใช้ แต่มาจากเครื่องเสมือนทดสอบก่อนปล่อยของ Google ทั้งสองครั้งเป็นฝั่งผู้ทดสอบที่พลาดก่อน

สารบัญ

  1. จะทดสอบตัวเก็บ ต้องให้แอปพังจริงก่อน
  2. ประเมินพลาดข้อแรก: เชื่อว่าส่งสัญญาณแล้วแอปต้องดับ
  3. ประเมินพลาดข้อสอง: เชื่อว่า error ที่เข้ามาหลังอัปโหลดเป็นของผู้ใช้
  4. แล้วผมเปลี่ยนอะไร
  5. ถ้าคุณอยู่ในสถานการณ์เดียวกัน ลองตามลำดับนี้

จะทดสอบตัวเก็บ ต้องให้แอปพังจริงก่อน

เวลาเกมพังบนมือถือ ผมอยากรู้ก่อนที่รีวิวจะเข้ามา เลยทำตัวเก็บ error เล็ก ๆ แล้วใส่ไว้ในเกมราวสิบเกม มันรับ error ของ webview การกระทำก่อนหน้านั้น และ native crash ที่ทำให้แอปหายไปทั้งตัว

ปัญหาอยู่ที่การทดสอบ ถ้าอยากรู้ว่าตัวเก็บจับ crash ได้ไหม แอปต้องดับจริง ผมจึงทำปุ่มบังคับให้แอปเด้งออกแยกต่างหาก กดปุ่มที่ซ่อนไว้ แล้วส่ง SIGSEGV (สัญญาณความผิดพลาดในการเข้าถึงหน่วยความจำ) ไปยังโพรเซสของแอป

ประเมินพลาดข้อแรก: เชื่อว่าส่งสัญญาณแล้วแอปต้องดับ

ผมกดปุ่มบน iPhone 11 Pro เครื่องจริง แต่แอปไม่ดับ หน้าจอเหมือนเดิม และตัวเก็บก็ไม่ได้รับอะไรเลย

ตอนนั้นข้อสรุปที่อันตรายที่สุดคือตัวเก็บจับ crash ไม่ได้ แต่ความจริงคือปุ่มต่างหากที่ทำให้แอปดับไม่ได้ ถ้าโทษตัวเก็บ ผมจะไปแก้โค้ดที่ปกติดีอยู่ แล้วทิ้งช่องโหว่จริงไว้ พอตรวจดูก็พบว่าต้นเหตุอยู่ที่ปุ่ม ตัวจัดการสัญญาณที่ webview ติดตั้งไว้แล้วดักสัญญาณนั้นไปก่อน

ที่แก้มีบรรทัดเดียว ก่อนส่งสัญญาณ ให้คืนค่า SIGSEGV กลับเป็นพฤติกรรมเริ่มต้น หลังจากนั้นแอปก็ดับ และในการเปิดครั้งถัดไป ทั้งบันทึกการปิดผิดปกติฝั่ง webview และรายงาน SIGSEGV ที่ iOS รวบรวมไว้ก็เข้ามาครบ วันนั้นผมได้เรียนรู้ว่าเครื่องมือทดสอบพลาดได้ก่อนสิ่งที่ถูกทดสอบ

ประเมินพลาดข้อสอง: เชื่อว่า error ที่เข้ามาหลังอัปโหลดเป็นของผู้ใช้

ตัวเก็บมีเกณฑ์ระดับความรุนแรง ถ้า error ตอนเปิดแอปภายใน 8 วินาทีแรกเกิดตั้งแต่ 2 รอบขึ้นไป ถือว่ารุนแรง และผมจะเตรียมแก้ด่วน (hotfix) ทันที สัปดาห์แรกมีสองเกมติดเกณฑ์นี้ คือ Wax Tower 1.0.10 และ Chichi Backpack 1.0.0 ที่เพิ่งขึ้น Play และทั้งสองเป็น error เดียวกัน คือการลิงก์ shader ล้มเหลว จำนวน uniform เท่ากับ 261

ผมอ่านว่าเกมของผมดับตอนเปิดบนมือถือผู้ใช้ แต่ไม่ใช่ ผมเปิด Wax Tower 1.0.10 บนมือถือทำงาน (Adreno 740) แล้ว error เป็น 0 ส่วนเลข 261 เป็นค่าขีดจำกัดของตัวเรนเดอร์ซอฟต์แวร์ (SwiftShader) ที่เครื่องเสมือนของ Google ใช้ error ของหุ่นยนต์ทดสอบก่อนปล่อยที่ Play รันทันทีหลังอัปโหลด ถูกผมนับเป็น error ของคนจริง

ที่ผมอ่านตอนแรกความจริง
เนื้อหา errorลิงก์ shader ล้มเหลวตอนเปิดแอป (uniform 261)error เดียวกัน เป็นค่าขีดจำกัดของเครื่องเสมือน
เกิดที่ไหนมือถือของผู้ใช้เครื่องเสมือน Firebase Test Lab (SwiftShader)
เวอร์ชัน 1.0.10 บนมือถือทำงาน (Adreno 740)ยังไม่ได้ตรวจerror 0
การประเมินความรุนแรง2 รายการที่ต้องแก้ด่วนไม่ต้องแก้ด่วน

แล้วผมเปลี่ยนอะไร

ตอนนี้ถ้าตัวเก็บรันบนตัวเรนเดอร์ซอฟต์แวร์หรืออุปกรณ์ firebase.test.lab มันจะไม่ส่งทั้งเซสชันและ error เลย ผมลองบนมือถือทำงานด้วยตัวเองแล้ว เปิดตัวบ่งชี้ก็ถูกจำว่าเป็นหุ่นยนต์ ปิดก็ถูกจำว่าเป็นคน และยังใส่ตัวกันนี้ในการตรวจการซิงก์ด้วย เพื่อไม่ให้มีสำเนาที่ขาดตัวกันนี้

สัปดาห์แรกได้กฎสองข้อ ปุ่มสำหรับทดสอบ ให้เช็กก่อนว่าปุ่มนั้นทำงานจริง ส่วนอุปกรณ์เฝ้าระวังตัวใหม่ ให้กรองสัญญาณรบกวนที่มันสร้างเองก่อน

ถ้าคุณอยู่ในสถานการณ์เดียวกัน ลองตามลำดับนี้

ถ้าคุณเป็นนักพัฒนาเกมคนเดียวที่เพิ่งติดตัวเก็บ error ผมแนะนำลำดับนี้

  • ถ้าเขียนโค้ดที่ตั้งใจให้แอปดับ ให้เช็กบนเครื่องจริงก่อนว่าแอปดับจริงไหม
  • หลังแอปดับ ดูต่อว่ารายงานเข้ามาในการเปิดครั้งถัดไปหรือไม่
  • error ที่เข้ามาทันทีหลังอัปโหลดขึ้น Play ให้เทียบกับรายชื่ออุปกรณ์ในรายงานก่อนปล่อยก่อน
  • error ที่น่าสงสัย ให้ลองทำซ้ำบนมือถือจริงเครื่องเดียวด้วยเวอร์ชันเดียวกัน
  • เกณฑ์แจ้งเตือนใหม่ ให้นับก่อนว่าในสัปดาห์แรกมันสร้างสัญญาณรบกวนเองกี่ครั้ง

FAQ

จะตั้งใจให้แอป iOS เด้งออกเพื่อทดสอบตัวเก็บ crash ได้อย่างไร

ผมใช้ปุ่มที่ส่งสัญญาณ SIGSEGV ไปยังโพรเซสของแอป บน iPhone 11 Pro เครื่องจริง ตัวจัดการสัญญาณที่ webview ติดตั้งดักไว้ แอปจึงไม่ดับ พอคืนค่า SIGSEGV เป็นพฤติกรรมเริ่มต้นก่อนส่ง แอปก็ดับ อย่าลืมดูด้วยว่ารายงานเข้ามาในการเปิดครั้งถัดไปหรือไม่

รายงานก่อนปล่อยของ Play Console มี crash ผู้ใช้จะเจอด้วยไหม

กรณีของผมไม่ใช่ เป็น error ของตัวเรนเดอร์ที่เกิดเฉพาะบนเครื่องเสมือน Firebase Test Lab ทันทีหลังอัปโหลด และเมื่อเปิด Wax Tower 1.0.10 บนมือถือจริง (Adreno 740) error เป็น 0 ลองดูรายชื่ออุปกรณ์ในรายงานก่อนปล่อยก่อน

ตัวเก็บ crash เก็บอะไรบ้าง
