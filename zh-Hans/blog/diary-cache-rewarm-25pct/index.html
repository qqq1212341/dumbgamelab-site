一人开发的 token 账本

一天的 token 浪费了 25%，其中 14.4% 是缓存重新预热

Justin Lee, Dumb Game Lab · 2026-11-18

10 月 28 日这一天计费的 token 是 90.6M，其中 22.7M（25%）进了浪费栏。最大的一栏是缓存重新预热 13.0M（占全部的 14.4%），超过浪费的一半。原因是我用手机开的两个对话会话一整天都没关，每多说一句，前面的对话就要从头重新写进缓存。

先看一天的账本

我一整天同时跑好几个 AI agent 做游戏。当天用掉的 token，晚上写日记时会把会话记录收集起来分栏统计，10 月 28 日的账本是这样的。

计费合计 90.6M。这是输入 33K、输出 9.6M 再加上缓存写入 80.9M 的总和，其中光是缓存写入就几乎占满了整个合计，所以第一次打开这本账时，我还以为是自己算错了。缓存写入占了 89.4%。缓存读取 2.61B 单价很低，不算进这个合计，另外单独记。

缓存重新预热是什么

对话式 AI 每收到一条新消息，都会把前面整段对话重新读一遍。提示词缓存（prompt caching）会把处理过一次的开头部分暂存起来，下一次请求就能用便宜的价格直接取用。

问题出在保存时间。按照 Anthropic 官方文档，缓存默认寿命是 5 分钟，每用一次就重新续上，另外也可以选 1 小时的版本。过了这段时间再发消息，就得把前面整段对话重新写进缓存。

价差很大。缓存写入是基础输入单价的 1.25 倍（5 分钟）或 2 倍（1 小时），读取只要 0.1 倍。同样一段前文，重新写入要付读取时的 12.5 到 20 倍。

元凶是一整天开着的两个手机会话

我的账本把歇了一小时以上才回来的主会话整段重新写进缓存的上下文量，记为「缓存重新预热」。那天把这一栏撑大的，是我用手机开着的两个会话。

一个开了 1,379 分钟，另一个开了 1,161 分钟，而一天只有 1,440 分钟，等于两个窗口都是早上打开后一直到深夜都没好好关过。差不多一整天。我想到什么就从手机丢一句过去，每丢一次，凉掉的对话就从头重新预热一次。

漏得最多的是以「怎么停了？」开头的瓶颈会话。它在 160 分钟里花了 4.8M 在缓存重新预热上。这个会话当天用掉的 7.5M 里，将近三分之二是重新预热。

连续 4 天第一，光靠嘴说没减下来

缓存重新预热从 10 月 25 日起连续 4 天都是浪费第一名。我每天都写进日记，也开了要修的工单。数字还是没降下来。

「会话要开短一点」这种决心，一拿起手机就忘了。路上想到什么要马上交代，比起开新窗口从头讲清楚情况，在原来的对话里补一句要省事得多。靠人的习惯撑着的规则，会一直在同一个地方漏。

第二栏：未合并 6.7M

浪费第二名是未合并 6.7M（7.4%）。用了很多 token、成果却一次都没进主代码的会话，就记在这一栏。

这一栏抓到的是首尔现况会话（103 分钟）和 Chichi 乱斗会话（47 分钟）。首尔那边把活交给子 agent，回了一句「进行中」就结束了。未合并和缓存重新预热加起来，首尔现况会话一共用了 2.4M。

所以换了做法

那天日记的第一条教训是：会话长度不会因为嘴上说说就变短。所以我不再下决心，改成装一个机制。会话超过预先定好的时间，就把到目前为止的内容整理成摘要存下来，再交给新会话接着做。

新会话只带着一份短摘要开始，需要重新预热的前文就很小。处境相同的话，可以先按下面的顺序量一量。

  • 把一天的 token 分成输入、输出、缓存写入、缓存读取记下来。
  • 缓存写入比例偏高时，先怀疑歇了一阵才回来的对话。
  • 数一数开得最久的会话开了多少分钟。
  • 超过一定时间的会话，留下摘要后重新开一个。
  • 同一栏连续好几天都是第一，就别再下决心，直接装机制。

FAQ

提示词缓存（prompt cache）是什么？

把前面处理过一次的提示词开头部分暂存起来，下一次请求时再拿来用的功能。按 Anthropic 文档，默认寿命是 5 分钟，每用一次就续上，也可以选 1 小时的版本。

提示词缓存的费用差多少？

按官方文档给的倍率，缓存写入是基础输入单价的 1.25 倍（5 分钟）或 2 倍（1 小时），缓存读取是 0.1 倍。同样的内容重新写入，要付读取时的 12.5 到 20 倍。

Claude Code 对话开太久，为什么 token 消耗会变多？

因为缓存过期之后再发消息，前面整段对话都要重新写进缓存。拿我来说，两个一整天开着的手机会话，让当天计费 90.6M 里有 13.0M 就这么花掉了。

Claude Code 的 token 用量怎么查询？

我把电脑上留下的 Claude Code 会话记录文件按天收集，分成输入、输出、缓存写入、缓存读取，再把歇了一阵才回来的缓存写入、没有成果就结束的会话这类浪费栏另外统计。数字要按栏摊开，才知道是哪里在漏。以前只看合计，只知道用得多，却不知道为什么。
