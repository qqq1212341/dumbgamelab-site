고쳐서 확인하는 데 40분, 5초짜리 길은 처음부터 있었습니다

Justin Lee, Dumb Game Lab · 2026-11-06

시험용 빌드가 맵 굽기와 실행 확인까지 전부 도는 전체 빌드 하나뿐이면, 버그 하나 확인하는 데 40분이 걸립니다. 코드만 바뀌었다면 스크립트 DLL만 다시 컴파일하는 빠른 판으로 같은 확인이 5초에 끝났습니다. 시험 고리는 빠른 판부터 만들고, 전체 빌드는 마지막에 한 번만 돌리는 순서가 맞습니다.

10월 27일, 같은 말이 두 번 나왔습니다

시험용 PC에서 실격 버그를 고친 날이었습니다. 고친 판을 확인하려고 빌드를 돌렸는데, 맵 5개를 굽고 실행 확인까지 하는 전체 빌드라 한 번에 40분이 걸렸습니다.

오후 4시 51분에 «왜 이렇게 오래 걸려, 빌드 말고 개발 모드로 하면 안 되나» 소리가 나왔습니다. 오후 6시 7분에는 «진짜 오래 걸리네, 제발 빠르게 해 주세요»가 나왔습니다. 두 번 다 맞는 말이었습니다.

그 뒤에 코드만 바뀌었을 때 스크립트 DLL만 컴파일하는 빠른 판 스크립트를 돌려 봤더니 5초에 끝났습니다. 그 길은 처음부터 있었는데 저는 쓰지 않았습니다.

40분과 5초 사이에 들어 있던 것

전체 빌드가 하는 일을 나눠 보면 맵 굽기, 플레이어 만들기, 실행해서 뜨는지 확인하기입니다. 출시 직전에는 전부 필요한 일입니다.

그런데 이번에 바뀐 건 실격 판정 코드 몇 줄이었습니다. 맵은 그대로인데도 5개를 다시 구웠습니다. 확인하려던 건 «고친 코드가 맞게 도는가» 하나였고, 그걸 보려고 나머지 전부를 40분 동안 기다렸습니다.

빠른 판은 이 과정을 뺐습니다. 바뀐 스크립트만 DLL로 컴파일하고, 이미 구워 둔 결과물은 그대로 씁니다. 같은 확인이 5초였습니다.

전체 빌드빠른 판
하는 일맵 5개 굽기 + 플레이어 만들기 + 실행 확인바뀐 스크립트 DLL 컴파일
걸린 시간약 40분약 5초
쓸 때출시 직전·맵이 바뀔 때코드만 바뀌었을 때

하루에 몇 번 고칠 수 있나

직접 계산해 보겠습니다. 하루 8시간을 전부 빌드에만 쓴다고 가정해도 40분짜리는 12번 남짓입니다. 확인하고 고치고 다시 확인하는 사이클이 하루 12번을 못 넘는다는 얘기입니다. 5초짜리라면 사이클 한 번에 1분도 안 걸립니다.

버그는 한 번에 안 잡힙니다. 고치고, 틀렸고, 다시 고치고, 또 틀립니다. 사이클 수가 곧 하루에 잡을 수 있는 버그 수입니다. 이날 제가 잃은 건 40분이 아니라 하루에 돌릴 수 있었던 사이클 대부분이었습니다.

이 숫자는 일기에 적힌 40분과 5초, 8시간이라는 가정으로 낸 계산입니다. 실제로 하루에 몇 번 돌렸는지는 세어 두지 않았습니다.

원인은 순서였습니다

시험 고리를 처음 만들 때 «빠른 판 먼저, 전체 빌드는 나중» 순서로 짠 게 아니었습니다. 전체 빌드 하나만 있었습니다. 빠른 판은 화가 난 뒤에야 개발 모드 스위치와 함께 생겼습니다.

누구 탓을 하자는 게 아니라 구조 얘기입니다. 시험 고리가 느리면 사람은 확인을 줄입니다. 확인이 줄면 고친 게 맞는지 모른 채 다음 일로 넘어갑니다. 느린 고리는 그냥 느린 데서 끝나지 않고 확인 자체를 안 하게 만듭니다.

새 시험 대상에 처음부터 까는 순서

이날 이후로 새 시험 대상에는 이 순서로 고리를 깝니다.

엔진마다 이름은 다르지만 비슷한 길이 있습니다. 유니티라면 개발용 빌드에서 스크립트만 다시 빌드하는 옵션이 있고, 에디터의 플레이 모드 옵션으로 도메인 리로드를 건너뛰는 길도 있습니다. 어느 쪽이든 요점은 같습니다. 바뀐 것만 다시 하는 길을 첫날 만들어 둡니다.

  • 첫날: 코드만 바뀐 판을 몇 초 안에 돌려 보는 길(빠른 판, 에디터에서 바로 실행)부터 만든다
  • 둘째: 개발 모드 스위치. 맵 굽기, 긴 연출, 광고처럼 확인과 상관없는 것을 끈다
  • 마지막: 전체 빌드는 출시 직전과 맵이 바뀐 날에만 돌린다
  • 시험 고리마다 «이 확인에 몇 초 걸리나»를 한 번 재 둔다

아직 못 고친 것

빠른 판 스크립트와 개발 모드 스위치는 생겼지만, 새 시험 대상이 첫날 빠른 판부터 깔게 하는 규칙이나 검사는 아직 없습니다. 지금은 티켓 한 장에 적어 둔 다짐일 뿐입니다. 다음 시험 대상에서 정말 첫날 깔리는지는 그때 확인하겠습니다.

FAQ

게임 빌드가 너무 오래 걸리면 어떻게 줄이나요?

전체 빌드가 하는 일을 나눠 보세요. 코드만 바뀌었다면 맵 굽기나 에셋 처리는 다시 할 필요가 없습니다. 바뀐 스크립트만 컴파일하는 빠른 판을 따로 만들고 전체 빌드는 출시 직전에만 돌리면, 확인 한 번이 40분에서 5초로 줄 수 있습니다.

스크립트만 다시 빌드하는 방법이 있나요?

유니티는 개발용 빌드에서 스크립트만 다시 빌드하는 옵션이 있고, 이전에 만든 플레이어가 있어야 쓸 수 있습니다. 에디터에서는 플레이 모드 옵션으로 도메인 리로드를 건너뛸 수도 있습니다. 엔진마다 이름이 다르니 쓰는 엔진 문서에서 «증분 빌드»나 «스크립트만 빌드»를 찾아보세요.

빠른 판만 쓰면 안 되나요?

안 됩니다. 빠른 판은 코드 확인용이라 맵, 에셋, 실제 플레이어 실행은 보지 못합니다. 출시 직전과 맵이 바뀐 날에는 전체 빌드를 한 번 돌려 둘을 맞춰 보는 게 안전합니다.
